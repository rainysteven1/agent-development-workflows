# Research Ideation

## Overview

An idea is only useful once it becomes testable. This skill turns research hunches into explicit hypotheses with measurable validation criteria.

## Validation Gate

Before an idea enters formal experimentation, it should have:

- a falsifiable hypothesis
- measurable success criteria
- an estimate of how fast signal can be obtained

If any of these are missing, the idea is still exploratory.

## Workflow

1. Capture the idea in one sentence.
2. Expand it into a hypothesis with expected effect and scope.
3. Define success criteria as metric, direction, and threshold.
4. Estimate cycle time.
5. Decompose the idea if validation would take too long.
6. Hand off validated ideas to `experiment-lab`.

## Practical Rules

- prefer hours-to-days feedback loops over week-scale loops
- use proxy metrics when full evaluation is too slow
- record pivots instead of rewriting history
- abandon weak ideas explicitly so they are not rediscovered later

## Suggested Artifacts

- `paper/ideas/<idea-id>.md`
- `notes/literature/` for targeted related work
- a lightweight prototype directory when feasibility is unknown
